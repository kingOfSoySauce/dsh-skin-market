# 失败与状态文案的多语言约定

范围：皮肤市场插件（host 与 client）里所有会出现在用户界面上的状态、进度与失败文案。
目标：界面永远是当前语言（zh/en 对齐），原始诊断只进日志与可复制的诊断内容。

## 1. 完成标准（验收）

界面满足下面三条即为完成：

1. **用户可见文本零裸原文**：alert、toast、按钮禁用原因、进度横幅、失败对话框正文（title/what/why/details）都通过 `messageKey` 渲染；界面里不再出现未翻译的中文句。
2. **zh / en 目录 key 集合一致**：`tests/client/i18n.spec.ts` 的 parity 断言通过，缺一边即失败。
3. **新增路径有覆盖**：新增的失败/状态路径至少有一条测试断言其 `messageKey`（已有失败分类测试也要保持通过）。

不满足这三条的属于“体验增强”，不阻塞发布；但新增代码不得再引入裸原文。

## 2. 机制：key 与原文并存

- 失败对象 `OperationFailure` 与路由错误响应同时携带 `message`（原文，byte-identical）和 `messageKey`/`messageParams`。
- 客户端优先用 `operationMessage({ message, messageKey, messageParams })`；未知 key（旧客户端）回退原文。
- 失败弹窗先按 `kind`/`code` 给出专门文案，再按 `messageKey` 兜底，最后才是通用文案。
- 服务端抛错用 `MarketMessageError(rawMessage, key, params?)`，raw 必须保持原样。

## 3. 允许保留原文的白名单

这些位置**故意**不做翻译，不算未完成：

- `failure.message` / `error` 等原始字段：classifier、旧客户端、日志导出依赖原文；
- 日志（`logEvent`，已做 token/路径脱敏）与“复制诊断”内容；
- pnpm / Host 的原始输出（`packageResult.output`、终端输出）；
- 机器码（如 `npm-package-not-found`、`ERR_PNPM_*`）作为参数或内部分类使用，不直接展示；
- 只存在状态里、不渲染的字段（例如 self-update 的 `updateBlockedReason`）。

## 4. 新增文案的规则

1. 文案先想清楚是“状态/进度”还是“失败原因”，分别加 `common.*` / `failure.*` key；
2. zh 与 en 同时补，不能只补一边；
3. 模板里不要塞另一种语言的自由文本参数（例如把中文 `assessment.reason` 塞进英文模板）；需要展示细节时保留原文到诊断，界面用通用句；
4. 失败路径优先复用已有 `kind`/`code` 映射；只有无法归类时才用 `messageKey` 兜底；
5. 改了任何 UI 文案后跑 `npx vitest run --config config/vitest.config.ts tests/client/i18n.spec.ts tests/client/failure-help.spec.ts`。

## 5. 当前已知的“通用标题”范围

约 85 处 `lifecycle.ts` 领域错误目前是“本地化通用标题 + 原因只进日志”。这属于体验增强（更具体的标题），不在完成标准内；做的时候按域分批，不要混进功能改动。
